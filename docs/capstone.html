90-day roadmap from fragmented pilots to a governed platform

Phase Weeks Outcomes
Foundation 1–4 AI use-case registry and risk tiering; model gateway with metering and baseline guardrails; identity integration (Entra / IAM, OBO); OpenTelemetry tracing; first golden eval set
Paved road 5–8 Shared ingestion and hybrid retrieval service with ACLs; prompt registry with CI eval gates; MCP gateway with 3–5 governed connectors; agent harness template with budgets and checkpoints
Scale 9–12 Migrate 2–3 highest-value pilots onto the platform; online evals and drift monitors; FinOps dashboards with unit economics; automated red-team suite; adoption playbook per persona

Maturity model

Level Name Characteristics
1 Experimenting Isolated PoCs, shared API keys, vibe checks, no inventory
2 Piloting A few apps in production, ad hoc guardrails, manual evals, cost visible per invoice only
3 Standardized Shared gateway and retrieval, eval gates in CI, use-case registry, tracing
4 Scaled Paved road for agents, MCP registry, OBO identity, FinOps unit economics, continuous red-teaming
5 Optimizing Portfolio routing and distillation, production eval flywheel, value tracking at board level, governance automated end to end

Choosing a cloud platform for a client

  1. Start from the estate. Where are the data, the identity provider and the operations skills? This usually decides the primary platform (Section 13).
  2. Check model access. Confirm the required models are available in the needed regions and capacity modes. All three platforms offer broad catalogs that increasingly overlap.
  3. Compare agent platforms on governance, not demos: identity per agent, policy enforcement outside the model, evaluation and tracing, private networking.
  4. Keep the seams portable: open frameworks, MCP tools, OpenTelemetry, a model gateway (13.14).
  5. Prove it on the client's eval set in a time-boxed pilot before committing at scale.
